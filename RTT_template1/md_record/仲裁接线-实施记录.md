1. `dev_polarity.c`

2. `dev_state.c`
   - `EMERGENCY` 入口：axis 0/1 各发送 `CMD_TYPE_EMERGENCY_STOP`，urgent=true；原轴事件 `EVT_ACT_HOLD` 保留。
   - `FAULT` 入口：axis 0/1 调用 `Arb_SetEnable(axis, RT_FALSE)`。
   - `FAULT -> RUN`：在 RUN 入口检查状态机 `previous_state == SYS_STATE_FAULT`，显式重新使能双轴，并按当前极性重发方向或 CLEAR 命令。
   - 发送与使能失败均走 `ARB_PRINT` 一行英文告警；状态机跳转表结构未重构。

## 三、恢复语义

- `FAULT -> IDLE`：`sys_enter_idle()` 继续调用 `Dev_Registry_InitAll()`；仲裁模块幂等复位并重新 enable，因此不额外补动作。
- `FAULT -> RUN`：该路径不经过 IDLE，也不会执行 `Dev_Registry_InitAll()`，FAULT 中被关闭的双轴必须显式 `Arb_SetEnable(axis, RT_TRUE)`。
- `FAULT -> RUN` 的方向来源使用 `Polarity_GetState()` 当前稳定态：FWD 重发 RUN_FWD，REV 重发 RUN_REV；UNKNOWN、掉电、异常状态发送 CLEAR_ALLOW_FWD 和 CLEAR_ALLOW_REV，保持无允许方向。
- 判定方法：RUN 入口读取 `mySystem.sys_sm.previous_state`，仅当上一状态是 FAULT 时执行 resync，避免把普通 IDLE -> RUN 或 STOP -> RUN 误判为故障恢复。
- resync 时通过 `SYS_STATE_PRINT("act resync from fault")` 打印来源，英文、整型。
