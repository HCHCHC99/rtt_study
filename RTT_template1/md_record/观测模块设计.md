## 一、需求背景

**目标**：新增观测模块，统一获取 Dev 下各模块与系统状态机的当前状态，**以全局变量形式暴露，放进 debugger Watch 实时查看**（RTT 打印为可选辅助）。

**观测对象**：
| 类别 | 模块 | 关键观测点 |
|---|---|---|
| 系统层 | 系统状态机 | 当前状态、故障码、事件集状态 |
| 设备层 | ADC 设备 | 采样状态、最新 AD 值、滑动均值 |
| | 母线电压 | 电压值（滤波+偏置）、状态（正常/过压/欠压）、阈值（过压/欠压/迟滞）、恢复延时 |
| | 电流传感器 | 电流值（10ms 均值）、状态（正常/过流）、阈值、时间窗口、当前超阈值累计 |
| | 电源极性 | 当前状态（FWD/REV/UNPOWERED/ABNORMAL） |
| 任务层 | DI 任务 | 运行状态、周期 |
| | LED 任务 | 运行状态、周期、GPIO 状态 |
| 管理层 | 设备注册表 | 已注册设备数、启用状态 |

## 二、决策（方案一：集中式观测器）

**决策内容**：
- 采用 **方案一（集中式观测器）**；
- 位置：`Dev/dev_monitor/`；
- 执行模型：**B 模式（协作周期），500ms 更新周期**；
- 打印：`rtt_manager.h` 的 `MONITOR_PRINT` 开关。

**决策理由（权重）**：
| # | 理由 | 权重 | 说明 |
|---|---|---|---|
| 1 | Debug 效率最高 | 40% | 所有观测信息集中在 dev_monitor.c，单点调试 |
| 2 | 符合项目规范 | 30% | dev_ 前缀 + dev_registry 注册 + MONITOR_PRINT |
| 3 | 数据一致性保证 | 20% | 周期性快照，同一时刻数据，便于时序分析 |
| 4 | 代码维护性 | 10% | 修改点集中，版本控制清晰 |

**决策签名**：架构师 / 开发负责人 / 测试负责人 均 ✅ 同意（2026-08-26）。

### 2.1 输出方式：Watch 全局变量（debug 首选）

**核心**：观测数据存**全局 volatile 结构体 `g_monitor`**，用 debugger Watch 窗口添加即可查看，**不依赖 RTT 打印**。

- 变量：`extern volatile Monitor_t g_monitor;`（结构见第五章）；
- 状态字段用**枚举类型**（`SysState_t` / `PolarityState_t` / 电压电流状态枚举），Watch 直接显示名称（如 `RUN` / `FWD` / `NORMAL`）；
- `Monitor_Task()` 周期性刷新 `g_monitor`（如 100ms），halt 时看到最近值；
- RTT `Monitor_DumpAll()` 保留为可选辅助，不开也行。

**操作步骤**：
- Keil µVision：Debug 会话 → View → Watch Window 1/2 → 添加 `g_monitor` → 展开字段；勾选 View → Periodic Window Update 可运行中周期刷新；
- RT-Thread Studio（Eclipse + GDB + J-Link）：Debug → 变量/监视（Expressions）→ 添加 `g_monitor`；GDB 需 halt 后查看（要运行中实时流可另用 J-Scope / RTT Viewer）。

> ⚠️ 要点：变量必须 **全局 + volatile**，否则编译器可能优化掉或 Watch 看不到更新；枚举字段必须用**枚举类型**声明，Watch 才显示名称而非数字。

## 三、方案对比（集中式 vs 分布式）

### 方案一：集中式观测器（已选）
- 创建 `Dev/dev_monitor/`，维护统一缓存结构；各模块通过 `GetXxxInfo()` 更新缓存，外部读缓存；
- 优点：单点调试、结构清晰、快照一致性、打印统一；
- 缺点：缓存有延迟（500ms）、扩展需改 monitor。

### 方案二：分布式观测器
- monitor 只统一调用各模块 `GetXxxInfo()` 并打印，不缓存；
- 优点：数据实时、模块自描述；
- 缺点：多点调试、接口不统一、多次调用非同一时刻快照。

**综合对比表**：
| 维度 | 方案一 集中式 | 方案二 分布式 |
|---|---|---|
| Debug 可读性 | ★★★★★ | ★★★☆☆ |
| 扩展便捷性 | ★★★★☆ | ★★★★★ |
| 数据时效性 | ★★★☆☆ | ★★★★★ |
| 数据一致性 | ★★★★★ | ★★★☆☆ |
| 代码维护性 | ★★★★★ | ★★★☆☆ |
| 接口统一性 | ★★★★★ | ★★★☆☆ |
| 内存开销 | ★★★☆☆ | ★★★★★ |
| 符合现有规范 | ★★★★★ | ★★★★☆ |

**结论**：选方案一，核心理由 = Debug 可读性 + 数据一致性 + 符合项目规范。

## 四、电源模块观测参数说明

### 4.1 母线电压模块（dev_bus_voltage）

**实时电压值**：`s_fVolt`（`BusVoltage_GetInfo()`）
- 处理流程：ADC 硬件采样（500us/2kHz）→ TMR0_1 硬件触发 + EOCA 中断维护 20 点滑动窗口（10ms）→ `Dev_Adc_GetMean(0, &fVolt)` → 分压换算（150k:10k，gain=16，ADC 层完成）→ **偏置补偿 +1.2V**（`VOL_OFFSET=1200.0f mV`，本模块添加）；
- 单位：V。

**状态**：0 正常 / 1 欠压 / 2 过压。

**阈值参数**：
| 参数 | 值 | 说明 |
|---|---|---|
| volt_over_th | 23.0 V | 过压阈值 |
| volt_under_th | 0.0 V | 欠压阈值 |
| volt_hyst | 2.0 V | 迟滞回差 |
| volt_recover_ms | 3000 ms | 恢复延时 |

**迟滞**：过压恢复需 < 21V；欠压恢复需 > 2V。

### 4.2 电流传感器模块（dev_cur_sensor）

**实时电流值**：`s_fCurrMa`（`CurrentSensor_GetInfo()`）
- 10ms 滑动均值（`Dev_Adc_GetMean(1, &fCurrMa)`）+ 绝对值 + 换算（VOUT=1650+IP*132 mV，gain=7575.7576）；
- 单位：mA。

**状态**：0 正常 / 1 过流（超阈值累计 ≥ 50ms）。

**阈值参数**：
| 参数 | 值 | 说明 |
|---|---|---|
| cur_over_th | 5000.0 mA | 过流阈值 5A |
| cur_over_window | 50 ms | 判定时间窗口 |
| cur_over_ms | 0~50 动态 | 当前超阈值累计（⚠️ 关键观测参数） |

**时间窗口机制（⚠️ 必须观测）**：
- 每 1ms 检测：超阈值则 `cur_over_ms++`（上限 50），否则清零；`cur_over_ms >= 50` 才判过流；
- 观测价值：提前预警（30ms 时还有 20ms 反应时间）、故障分析（瞬态/持续/临界过流）、策略调整（改窗口）、保护逻辑验证。

### 4.3 电源极性模块（dev_polarity）

**当前状态**：`Polarity_GetState()` → UNKNOWN / UNPOWERED / FWD / REV / ABNORMAL
- 硬件：POWER_DIR_P=PB13、POWER_DIR_N=PB12；
- 双窗口消抖：5 点窗口 × Task/di_task 2ms 采样 = 10ms 消抖；
- 事件：`EVT_ACT_POLARITY_FWD / REV / POWER_ABNORMAL / POWER_LOST`（发轴事件组）。

### 4.4 接口扩展需求

**问题**：`cur_over_ms` 是 `dev_cur_sensor.c` 内部变量，外部无法获取。
**方案**：`dev_cur_sensor.h` 新增查询接口（volatile，线程安全，最小修改，作为观测器前置条件）：
```c
uint16_t CurrentSensor_GetOverMs(void);   /* 返回 s_u16OverMs */
```

## 五、数据结构设计

**一个全局结构体 `g_monitor`，所有观测值集中，Watch 直接添加即可**：

```c
/* dev_monitor.h */
#include "Dev/dev_mgr/dev_state.h"      /* SysState_t */
#include "Dev/dev_power/dev_polarity.h" /* PolarityState_t */

/* 电压/电流状态枚举（便于 Watch 显示名称） */
typedef enum { VOLT_NORMAL = 0, VOLT_UNDER, VOLT_OVER } MonitorVoltSt_t;
typedef enum { CUR_NORMAL = 0, CUR_OVER }                MonitorCurSt_t;

typedef struct {
    /* 系统 */
    SysState_t      sys_state;       /* 系统状态：枚举，Watch 显示 RUN/FAULT 等 */
    uint32_t        error_code;      /* 故障码 0=NONE 1=OC 2=OV 3=UV */
    uint32_t        sys_events;      /* 系统事件组当前值 */
    uint32_t        uptime_ms;       /* 运行时间 */

    /* ADC */
    uint16_t        adc_raw_v, adc_raw_i;   /* 最新原始 AD */
    float           adc_mean_v, adc_mean_i; /* 10ms 均值 */

    /* 母线电压 */
    float           bus_volt;        /* 滤波+偏置后 V */
    MonitorVoltSt_t volt_status;     /* 枚举：NORMAL/UNDER/OVER */

    /* 电流传感器 */
    float           cur_ma;          /* 10ms 均值 mA */
    MonitorCurSt_t  cur_status;      /* 枚举：NORMAL/OVER */
    uint16_t        cur_over_ms;     /* 超阈值累计 */

    /* 阈值配置：显示镜像 + 指针（Watch 改 volt_cfg/cur_cfg 实时生效） */
    float    volt_over_th;
    float    volt_under_th;
    float    volt_hyst;
    uint32_t volt_recover_ms;
    float    cur_over_th;
    uint16_t cur_over_window;
    volatile VoltCfg_t *volt_cfg;   /* 指向 g_volt_cfg */
    volatile CurCfg_t  *cur_cfg;    /* 指向 g_cur_cfg */

    /* 电源极性 */
    PolarityState_t polarity;        /* 枚举：UNKNOWN/UNPOWERED/FWD/REV/ABNORMAL */

    /* 任务 */
    uint8_t         di_running;
    uint16_t        di_period_ms;
    uint8_t         led_running;
    uint8_t         led_state;
    uint16_t        led_period_ms;
} Monitor_t;

/* 全局观测变量：debugger Watch 直接添加 g_monitor */
extern volatile Monitor_t g_monitor;
```

**API**：
```c
void Monitor_Init(void);
void Monitor_Task(void);          /* 刷新 g_monitor（B 模式周期调用） */
void Monitor_DumpAll(void);       /* 可选：RTT 打印 g_monitor 全部 */
void Monitor_DumpSys(void);
void Monitor_DumpDev(void);
void Monitor_DumpTask(void);
```

## 六、执行模型与注册配置

**执行模型**：B 模式（协作周期），500ms。

```c
/* Dev/dev_config.h */
#define DEV_ENABLE_MONITOR    1
#define DEV_PRIO_MONITOR      DEV_PRIO_LOW

/* Dev/dev_registry.c */
#if DEV_ENABLE_MONITOR
    extern void Monitor_Init(void);
    extern void Monitor_Task(void);
    static const SysModule_t s_monitor_module =
        SYS_MODULE_REGISTER("monitor", Monitor_Init, Monitor_Task,
                            DEV_PRIO_MONITOR, 500);
    Dev_Registry_Add(&s_monitor_module);
#endif
```

> 注：目前 registry 的 `Dev_Start()` 未启用（电源链走 ISR/Task）。观测器要跑起来，需恢复 `Dev_Start()`（或观测器单独建线程），实施时二选一。

### 7.1 状态枚举名打印（debug 可读性）

**需求**：debug 时直接看**状态名**（枚举名）。Watch 方式下，字段用枚举类型声明即可自动显示名称（如 `RUN` / `FWD`），**无需手动映射表**；下面名称表仅用于**可选的 RTT 打印**。

**映射表**（Monitor 内部静态查表）：
| 字段 | 枚举 | 名称 |
|---|---|---|
| 系统状态 | SYS_STATE_INIT/IDLE/RUN/FAULT/EMERGENCY/STOP | INIT / IDLE / RUN / FAULT / EMERGENCY / STOP |
| 故障码 | SYS_ERR_NONE/OVER_CURRENT/VOLT_OVER/VOLT_UNDER | NONE / OC / OV / UV |
| 电压状态 | 0/1/2 | NORMAL / UNDER / OVER |
| 电流状态 | 0/1 | NORMAL / OVER |
| 电源极性 | POLARITY_UNKNOWN/UNPOWERED/FWD/REV/ABNORMAL | UNKNOWN / UNPOWERED / FWD / REV / ABNORMAL |

**实现**（名称表 + 查表打印）：
```c
static const char *const s_sys_state_name[] = {
    "INIT", "IDLE", "RUN", "FAULT", "EMERGENCY", "STOP",
};
static const char *const s_err_name[] = { "NONE", "OC", "OV", "UV" };
static const char *const s_volt_st_name[] = { "NORMAL", "UNDER", "OVER" };
static const char *const s_cur_st_name[] = { "NORMAL", "OVER" };
static const char *const s_pol_name[] = {
    "UNKNOWN", "UNPOWERED", "FWD", "REV", "ABNORMAL",
};
```

**Dump 示例（状态字段一律打名称）**：
```c
void Monitor_DumpAll(void) {
    MONITOR_PRINT("sys=%s err=%s",
                  s_sys_state_name[g_monitor.sys_state],
                  s_err_name[g_monitor.error_code]);
    MONITOR_PRINT("volt=%s cur=%s pol=%s",
                  s_volt_st_name[g_monitor.volt_status],
                  s_cur_st_name[g_monitor.cur_status],
                  s_pol_name[g_monitor.polarity]);
    MONITOR_PRINT("volt=%lumV cur=%lumA over_ms=%ums",
                  (uint32_t)(g_monitor.bus_volt * 1000.0f),
                  (uint32_t)g_monitor.cur_ma,
                  g_monitor.cur_over_ms);
}
```

**输出示例**：
```
[MON] sys=RUN err=NONE
[MON] volt=NORMAL cur=NORMAL pol=FWD
[MON] volt=24364mV cur=116mA over_ms=0ms
```

> **系统状态机取值来源**：当前无 `Sys_State_GetInfo()`，Monitor 用 `StateMachine_GetState(&mySystem.sys_sm)` 读系统状态、`mySystem.error_code` 读故障码（见附录）；后续可封装 `Sys_State_GetInfo()` 统一。

**Monitor_Task 刷新 g_monitor 示例**：
```c
void Monitor_Task(void) {
    /* 系统 */
    g_monitor.sys_state  = (SysState_t)StateMachine_GetState(&mySystem.sys_sm);
    g_monitor.error_code = mySystem.error_code;
    g_monitor.sys_events = (mySystem.sys_evt != RT_NULL) ? mySystem.sys_evt->set : 0U;
    g_monitor.uptime_ms  = rt_tick_get();

    /* ADC */
    Dev_Adc_GetRaw(0, &g_monitor.adc_raw_v);
    Dev_Adc_GetRaw(1, &g_monitor.adc_raw_i);
    (void)Dev_Adc_GetMean(0, &g_monitor.adc_mean_v);
    (void)Dev_Adc_GetMean(1, &g_monitor.adc_mean_i);

    /* 母线电压 */
    { uint8_t st; BusVoltage_GetInfo(&g_monitor.bus_volt, &st);
      g_monitor.volt_status = (MonitorVoltSt_t)st; }

    /* 电流传感器 */
    { uint8_t st; CurrentSensor_GetInfo(&g_monitor.cur_ma, &st);
      g_monitor.cur_status  = (MonitorCurSt_t)st;
      g_monitor.cur_over_ms = CurrentSensor_GetOverMs(); }

    /* 电源极性 */
    g_monitor.polarity = Polarity_GetState();
}
```

**Monitor_DumpDev 打印示例（可选，读 g_monitor）**：

## 九、高级功能扩展

1. **周期性自动打印**：`Monitor_Task` 内 `rt_tick_get() - last >= 5000` 时调 `Monitor_DumpAll()`；
2. **MSH 命令**：`MSH_CMD_EXPORT(cmd_monitor, "monitor system/device/task status")`；
3. **变化触发打印**：缓存状态变化时打印（如 sys_state 跳变）。

---

## 十、关键设计原则

1. 遵循现有规范：dev_ 前缀、dev_registry 注册、MONITOR_PRINT（不中文/不浮点）；
2. 最小侵入：只调现有 GetXxxInfo()，不修改现有模块逻辑；
3. 线程安全：观测模块只读；缓存 volatile；ISR 不调观测接口；
4. 可扩展：新模块 = 加字段 + Task 更新 + Dump 打印，三处修改集中在 dev_monitor。
