# 电源模块观测参数评估

> 评估日期：2026-08-26
> 评估对象：母线电压模块（dev_bus_voltage）、电流传感器模块（dev_cur_sensor）
> 结论：✅ 确认需要观测过流检测时间窗口（`cur_over_ms`）与电源极性状态（`Polarity_GetState()`）

---

## 一、评估背景

观测器需要获取电源模块的实时状态和关键参数，用于：
1. Debug调试时快速定位电源故障原因
2. 运行时监控系统健康状态
3. 分析过压/欠压/过流保护触发的时序
4. 预警即将触发的保护动作

---

## 二、母线电压模块（dev_bus_voltage）

### 2.1 需要观测的参数

| 参数 | 类型 | 单位 | 说明 | 获取方式 |
|------|------|------|------|---------|
| 实时电压值 | float | V | 滤波+偏置后的电压值 | `BusVoltage_GetInfo()` |
| 电压状态 | uint8_t | - | 0=正常 1=欠压 2=过压 | `BusVoltage_GetInfo()` |
| 过压阈值 | const float | V | 23.0V | 宏 `VOL_OVER_TH` |
| 欠压阈值 | const float | V | 0.0V | 宏 `VOL_UNDER_TH` |
| 迟滞回差 | const float | V | 2.0V | 宏 `VOL_HYST` |
| 恢复延时 | const uint32_t | ms | 3000ms | 宏 `VOL_RECOVER_DELAY_MS` |

### 2.2 电压值处理流程

```
ADC硬件采样（500us，2kHz）
    ↓
TMR0_1硬件触发 + EOCA中断
    ↓
20点滑动窗口（10ms）
    ↓
Dev_Adc_GetMean(0U, &fVolt)  ← 10ms滑动均值，单位V
    ↓
分压换算（150k:10k，gain=16.0）← ADC层完成
    ↓
偏置补偿：fVolt += 1.2V       ← 本模块添加（VOL_OFFSET）
    ↓
s_fVolt（观测器读取此值）
```

### 2.3 电压状态判定逻辑

```c
if (电压 > VOL_OVER_TH)          // > 23V
    → 过压状态（2）
else if (电压 < VOL_UNDER_TH)    // < 0V
    → 欠压状态（1）
else
    → 正常状态（0）

// 恢复条件（带迟滞）
过压恢复：电压 < (VOL_OVER_TH - VOL_HYST)      // < 21V
欠压恢复：电压 > (VOL_UNDER_TH + VOL_HYST)     // > 2V

// 恢复延时：故障解除后需持续3秒（3000ms）才真正恢复
```

### 2.4 观测价值

- **实时电压值**：监控电源质量，分析电压波动
- **电压状态**：快速判断当前是否在保护状态
- **阈值参数**：便于Debug时确认保护逻辑是否正确
- **迟滞回差**：分析保护解除的时序
- **恢复延时**：确认保护解除的等待时间

### 2.5 实施难度

- ✅ **无需修改现有接口**：所有参数均可通过现有接口获取
- ✅ **阈值是编译期常量**：直接读取宏定义即可
- ✅ **数据安全**：`s_fVolt` 是 `volatile`，线程安全

## 三、电流传感器模块（dev_cur_sensor）

### 3.1 需要观测的参数

| 参数 | 类型 | 单位 | 说明 | 获取方式 |
|------|------|------|------|---------|
| 实时电流值 | float | mA | 10ms滑动均值，已取绝对值 | `CurrentSensor_GetInfo()` |
| 电流状态 | uint8_t | - | 0=正常 1=过流 | `CurrentSensor_GetInfo()` |
| 过流阈值 | const float | mA | 5000.0mA（5A） | 宏 `CUR_OVER_CUR_TH_MA` |
| **时间窗口** | const uint16_t | ms | 50ms | 宏 `CUR_OVER_WINDOW_MS` |
| **当前超阈值累计** | uint16_t | ms | 0~50ms（动态） | ⚠️ 需要新增接口 |

### 3.2 电流值处理流程

```
ADC硬件采样（500us，2kHz，与电压共用）
    ↓
20点滑动窗口（10ms）
    ↓
Dev_Adc_GetMean(1U, &fCurrMa)  ← 10ms滑动均值，单位mA
    ↓
绝对值处理                     ← ADC层完成
    ↓
传感器换算：
  VOUT(mV) = 1650 + IP(A) × 132
  gain = 7575.7576
  offset = -12500.0
    ↓
s_fCurrMa（观测器读取此值）
```

### 3.3 过流检测逻辑（⚠️ 关键机制）

```c
// 1ms ISR检测（由TMR0_2心跳调用）
void CurrentSensor_Isr1ms(void) {
    // 获取10ms滑动均值
    Dev_Adc_GetMean(1U, &fCurrMa);
    s_fCurrMa = fCurrMa;

    // 时间窗口判定
    if (fCurrMa > CUR_OVER_CUR_TH_MA) {  // > 5000mA
        if (s_u16OverMs < CUR_OVER_WINDOW_MS) {
            s_u16OverMs++;  // 累计超阈值时间
        }
        if (s_u16OverMs >= CUR_OVER_WINDOW_MS) {  // ≥ 50ms
            s_u8Status = 1;  // 过流状态
        }
    } else {
        s_u16OverMs = 0;    // 清零
        s_u8Status = 0;     // 正常状态
    }

    // 跳变时发事件
    if (s_u8Status != u8Prev && s_u8Status == 1) {
        Sys_Event_Send(EVT_SYS_OVER_CURRENT);
    }
}
```

### 3.4 时间窗口机制详解

**为什么需要时间窗口**：
1. **抗瞬态干扰**：电机启动、负载突变时，电流可能短时超过阈值，但很快恢复
2. **避免误触发**：机械惯性导致的电流尖峰不应该触发保护
3. **区分故障类型**：
   - 瞬态过流：`cur_over_ms` < 50ms，自动清零，不触发保护
   - 持续过载：`cur_over_ms` ≥ 50ms，触发保护

**时间窗口工作原理**：
```
每ms检测一次电流：
  if (电流 > 5000mA) {
      cur_over_ms++;      // 累计
      if (cur_over_ms >= 50ms) {
          过流保护触发！
      }
  } else {
      cur_over_ms = 0;    // 清零（复位）
  }
```

### 3.5 观测 `cur_over_ms` 的价值

#### 3.5.1 预警机制

**场景**：电机即将卡死
```
时间  电流(mA)  cur_over_ms  观测器输出        动作
0ms   2000     0            cur_over_ms=0     --
10ms  5100     10           cur_over_ms=10    --
20ms  5300     20           cur_over_ms=20    --
30ms  5500     30           cur_over_ms=30    ⚠️ 预警："即将过流（20ms后触发），降速中..."
40ms  4800     0            cur_over_ms=0     ✅ 降速成功，避免保护触发
```

**价值**：在保护触发前20ms预警，提前采取措施避免停机。

#### 3.5.2 故障分析

**场景1：正常启动（瞬态过流）**
```
时间  电流(mA)  cur_over_ms  状态   分析
0ms   2000     0            正常   --
10ms  4500     0            正常   未超阈值
20ms  5200     10           正常   瞬态超阈值，累计10ms
30ms  4800     0            正常   已回落，清零
40ms  2100     0            正常   稳定
→ 结论：正常启动，未触发保护
```

**场景2：负载卡死（持续过载）**
```
时间  电流(mA)  cur_over_ms  状态   分析
0ms   2000     0            正常   --
10ms  5300     10           正常   开始过流
20ms  5600     20           正常   持续过流
30ms  5800     30           正常   临界状态（还有20ms触发）
40ms  6100     40           正常   接近触发
50ms  6200     50           过流   保护触发！
→ 结论：负载卡死，保护正确触发
```

**场景3：临界过流（反复触发）**
```
时间  电流(mA)  cur_over_ms  状态   分析
0ms   2000     0            正常   --
10ms  5100     10           正常   开始累积
20ms  5300     20           正常   累积中
30ms  4900     0            正常   下降，清零
40ms  5200     10           正常   重新累积
50ms  5400     20           正常   累积中
→ 结论：临界过流，电流在阈值附近波动，建议调整阈值或优化控制
```

**价值**：通过 `cur_over_ms` 的变化趋势，准确判断故障类型。

#### 3.5.3 策略调整

**应用场景1：工业设备（抗干扰优先）**
```
当前配置：CUR_OVER_WINDOW_MS = 50ms
问题：环境中电磁干扰强，导致误触发
调整：CUR_OVER_WINDOW_MS = 100ms  （延长窗口，提高抗干扰性）
验证：观测 `cur_over_ms` 分布，确认延长后误触发减少
```

**应用场景2：精密设备（快速保护优先）**
```
当前配置：CUR_OVER_WINDOW_MS = 50ms
问题：过流响应不够快，可能损坏设备
调整：CUR_OVER_WINDOW_MS = 20ms  （缩短窗口，快速保护）
验证：观测 `cur_over_ms`，确认缩短后保护及时
```

**应用场景3：根据负载动态调整**
```
if (负载类型 == 重载) {
    cur_over_window = 100ms;  // 允许更长时间
} else if (负载类型 == 轻载) {
    cur_over_window = 30ms;   // 快速保护
}
→ 通过观测 `cur_over_ms` 的历史记录，优化不同负载下的窗口参数
```

**价值**：基于实际数据优化保护策略，提高系统适应性。

### 3.6 是否需要观测 `cur_over_ms`？

#### 评估结论：✅ **必须观测**

**理由**：

1. **预警价值**（权重40%）
   - 提前20ms预警即将触发的保护
   - 为控制系统留出反应时间
   - 避免保护触发导致停机

2. **故障分析价值**（权重30%）
   - 区分瞬态过流 vs 持续过载
   - 识别临界过流模式
   - 快速定位误触发原因

3. **策略优化价值**（权重20%）
   - 基于实际数据调整时间窗口参数
   - 优化不同负载下的保护策略
   - 提高系统适应性和鲁棒性

4. **保护验证价值**（权重10%）
   - 验证时间窗口逻辑正确性
   - 确认保护触发时序
   - 快速排查保护相关bug

**不观测的后果**：
- ❌ 无法预警即将触发的保护
- ❌ 难以区分瞬态干扰和真实故障
- ❌ 无法基于数据优化保护策略
- ❌ 保护逻辑故障难以排查

## 四、电源极性模块（dev_polarity）

### 4.1 需要观测的参数

| 参数 | 类型 | 单位 | 说明 | 获取方式 |
|------|------|------|------|---------|
| 当前状态 | PolarityState_t | - | UNKNOWN/UNPOWERED/FWD/REV/ABNORMAL | `Polarity_GetState()` |
| 消抖窗口 | const uint8_t | 点 | 5 点（P/N 各 5，双窗口） | 宏 `POLARITY_WIN_SIZE` |
| 采样周期 | const uint32_t | ms | 2ms（Task/di_task） | 宏 `DI_SCAN_PERIOD_MS` |
| 消抖时长 | - | ms | 5 x 2ms = 10ms | 窗口点数 x 采样周期 |
| 状态事件 | const | - | FWD/REV/ABNORMAL/POWER_LOST | `dev_event_def.h` |

### 4.2 状态判定逻辑（双窗口消抖）

- P 窗口 = POWER_DIR_P（PB13）最近 5 次采样；N 窗口 = POWER_DIR_N（PB12）最近 5 次采样；
- 两个窗口都满 5 点且各自全一致，才判定稳定状态：
  - P=0 N=0 → 掉电（UNPOWERED）
  - P=1 N=0 → 正向（FWD）
  - P=0 N=1 → 反向（REV）
  - P=1 N=1 → 异常（ABNORMAL）
- 窗口未满 / 任一窗口不稳定 → UNKNOWN，保持上次稳定状态，不发事件；
- 状态跳变沿才发轴事件（EVT_ACT_POLARITY_FWD/REV/POWER_ABNORMAL/POWER_LOST）。

### 4.3 观测价值

- 上电确认电源极性（决定伸出/缩回的方向语义）；
- 运行中极性突变 = 接线/电源异常，可快速定位；
- 结合掉电事件（EVT_ACT_POWER_LOST）监控电源通断；
- 调试时确认双窗口消抖是否按预期工作（10ms）。

### 4.4 实施难度

- ✅ 无需修改接口：`Polarity_GetState()` 已存在；
- ✅ 无风险：只读接口；
- ✅ 数据安全：`s_state` volatile，线程安全。
