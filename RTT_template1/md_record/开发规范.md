# 工程开发规范（HC32F460 + RT-Thread）

> 记录日期：2026-08-25
> 范围：打印 / 注册 / 时间基准 / 采样参数 / 主要接口

## 1. 打印规范

- **统一走 `applications\rtt_manager.h` 的模块开关宏**：
  `SYS_STATE_PRINT`（状态机）、`DEV_REG_PRINT`（注册）、`POWER_PRINT`（电源设备）、`POLARITY_PRINT`（电源极性）、`LED_PRINT`（LED）、`MONITOR_PRINT`（监视）、`QUEUE_INIT_PRINT`（示例）。
- 所有打印最终落到 `MAIN_D`（经 `rtt_log.h`）。
- **英文、不打印中文**。
- **不打印浮点**：浮点拆整型（电压用 `%umV`；电流拆整数 + 1 位小数 `%u.%01u`）。
- 关闭某类打印：`rtt_manager.h` 里对应 `_EN` 置 0，重新编译，业务代码不用动。
- 开关宏命名：`XXX_PRINT_EN` 做开关（0/1），`XXX_PRINT(fmt, ...)` 做打印（避免同名重定义警告）。

## 2. 集中注册规范

- `Dev\dev_config.h`：功能开关 `DEV_ENABLE_XXX`（1/0）+ 优先级常量 `DEV_PRIO_HIGH/MID/LOW`。
- `Dev\dev_registry.c` 的 `Dev_RegisterAll()`：用 `#if DEV_ENABLE_XXX` 块集中注册。
- 设备文件**不再各自写 `Xxx_Register()`**，只保留 `Xxx_Init / Xxx_Task / Xxx_GetInfo`。
- 加设备：`dev_config.h` 加开关 + `Dev_RegisterAll` 加一个 `#if` 块。
- **init 时机（2026-08-26 改）**：注册时**不 init**；由状态机 IDLE 入口统一调 `Dev_Registry_InitAll()`（上电一次 + 每次进 IDLE 复位业务状态）；main 不再重复初始化。

## 3. 时间基准

| 时间源 | 精度 | 说明 |
|---|---|---|
| RT-Thread tick（`RT_TICK_PER_SECOND=1000`） | **1ms** | `rt_tick_get()` / `rt_thread_mdelay()` |
| `rt_hw_us_delay(us)` | µs（忙等） | RT-Thread 官方，本 BSP 在 `board\board.c` 实现（SysTick 忙等） |
| `DDL_DelayUS(us)` / `DDL_DelayMS(ms)` | µs/ms | HC32 DDL 硬件延时 |

- ⚠️ **没有 `rt_thread_udelay()`**——µs 延时只有忙等（CPU 空转，不做线程调度）。
- ADC 采样：**TMR0_1 硬件触发 500µs/2kHz**（`ADC_SAMPLE_INTERVAL_US=500U`，AOS 事件路由 + EOCA 中断维护 20 点/10ms 滑动窗口；1ms 检测走 TMR0_2 心跳，见 移植电压电流.md 第 8 节）。
- **us 计时器**：通用接口 `Utils\us_timer`（`UsTimer_Bind/Init/Start/GetTimestampUs`），实现 `Adp\hc_drv_timer`（HC32 TMR6，`hc_us_timer_ops`），换芯片只换 Adp。

| 监视打印 | main 循环每 1s 一次 `monitor_sample_1s()` → `[MON] t=...us AD=... avg=... cur=... vol=...`（含 TMR6 us 时间戳） |

## 5. 主要接口

- `dev_adc_ops`（`Dev\dev_adc\dev_adc_ops.h`）：`init / start / stop / get_latest / get_raw / read_ring / get_mean`
- `Dev_Adc_Bind(&hc32_adc_ops)`：绑定底层驱动（换芯片只改这行）
- `Dev_Adc_GetRaw(id, &raw)`：最近一次**原始 AD 值**
- `Dev_Adc_GetMean(id, &val)`：**10ms 滑动窗口平均**（换算后工程值，1ms 检测 ISR 用）
- `Dev_Adc_Start()` / `Dev_Adc_Stop()`：启动/停止 TMR0_1 硬件触发采样（500us/2kHz）
- `Dev_Adc_ReadRing(id, buf, max)`：读环形缓冲（换算后的工程值）
- `Dev_Adc_GetLatest(&v, &c)`：最近一次换算值（V / mA）
- `Sys_Event_Send(bits)` / `Act_Event_Send(bits)` / `Sys_State_Recover()`：系统事件 / 轴事件广播（ISR 安全）/ 手动恢复
- `Polarity_Scan / Polarity_GetState / Polarity_PrintPending`：电源极性（PB13/PB12 双窗口 5 点，Task/di_task 2ms 采样 => 10ms 消抖，跳变发轴事件，见 模块运行设计.md 第九节）
- `UsTimer_Bind/Init/Start/UpdateTimestamp/GetTimestampUs`：通用 us 计时器（Utils，实现 Adp/hc_drv_timer）

## 7. RT-Thread Studio 的 DDL 驱动排除列表（.cproject）⚠️

### 现象

Studio 的 `.cproject` 在 `libraries` 源文件夹上有一份 `excluding=` 排除列表，里面是**默认不编译**的 DDL 驱动（模板按"用到的才编"生成）。`|` 分隔的每一项 = 一个不编译的文件。

```xml
<entry excluding="//libraries/.../hc32_ll_aes.c|..." kind="sourcePath" name="libraries">
```

### 坑：要用某个 DDL 驱动，光加 SConscript 没用

Studio 的构建模型来自 `.cproject`（不是 SConscript）。所以要用某个 DDL 驱动，必须同时做三件事：

1. **DDL SConscript 加源码**（scons / Keil 用）：`libraries\hc32f460_ddl\SConscript` 里 `src += [...]`；
2. **`.cproject` 排除列表摘掉对应 .c**（Studio 用）：删掉 `//libraries/hc32f460_ddl/drivers/hc32_ll_driver/src/hc32_ll_xxx.c|`；
3. **关掉 Studio 重开 + 重新导入工程**：否则 makefile 不更新，链接仍报未定义。

### 已踩过的坑

> ✅ 2026-08-25：TMR0（hc32_ll_tmr0.c）与 AOS（hc32_ll_aos.c）**本就不在排除列表**、SConscript 已编译（tmr0 随 RT_USING_SERIAL），500us 硬件触发 + 1ms 心跳**无需改 .cproject**；用新外设时先查这两处再动手。

- `hc32_ll_adc.c`（ADC 采样）——靠摘排除列表解决；
- `hc32_ll_tmr6.c`（TMR6 us 时间基准）——靠摘排除列表解决。

### 实测（2026-08-25）

被排除的 23 个 DDL 驱动里：
- **22 个能编译**：aes / can / cmp / crc / dcu / emb / event_port / fcm / hash / i2c / i2s / keyscan / mpu / ots / qspi / rtc / sdioc / swdt / tmr4 / tmra / trng / wdt；
- **1 个不能**：`hc32_ll_usb.c`（依赖 `usb_app_conf.h`，工程没有，需 USB 中间件配置）。

### 原则：用到哪个放哪个

- 排除列表维持**最小化**（23 个不用的继续排除）；
- **不建议全放**：①未用函数会被 `--gc-sections` 裁掉，不占实际 flash，全放无收益；②会造成 Studio/Keil 构建清单不一致；③`usb` 放出来会编译报错。

## 8. 开发注意：脚本批量替换易"静默失败"⚠️

- 用 PowerShell / 脚本做字符串替换时，**模式没匹配上不会报错**，只会"没改"——容易误以为改好了。
- 本项目已踩过 3 次：`dev_state.c` 的 include、`monitor_sample_1s` 定义、`Timer6_Timebase_Init` 调用，都是"替换静默失败"导致固件缺功能。
- **规则**：每次替换后必须验证（grep 确认新内容在 / 旧内容无残留），再编译；
- PowerShell 单引号里 `` `r`n `` 是字面量（不是换行），跨行替换要用正则或真实换行符。
- **2026-08-26 新坑**：删 .c 里的宏时用了跳过块逻辑（匹配起始注释后跳过直到结束标记），结束标记没匹配上导致整个 .c 被删空（hc32_drv_adc.c 只剩 13 行，编译通过但链接 undefined reference）。教训：批量删行后必须检查文件行数 + nm 验证符号，不能只看单文件编译。

## 9. 设备模块执行模型（A/B/C）⚠️

RTOS 下设备 update 有三种执行模型，可混用；完整设计见 `md_record\模块运行设计.md`：

| 模型 | 做法 | 适合 |
|---|---|---|
| **A ISR 驱动** | 定时器/外设中断做最轻 update（采样/标志/事件），重活丢线程 | 高频、硬实时（电源采样/霍尔测速/保护） |
| **B 协作周期** | 共享 dev 线程按 `period_ms` 调 `task`（`Dev_Registry_UpdateAll`） | 中频、数字输入消抖、非硬实时 |
| **C 独立线程** | 每模块一线程，`rt_event_recv / rt_sem_take / rt_queue` 阻塞等活 | 阻塞 IO（通讯）、事件驱动逻辑（仲裁/状态机） |

- **现状**：电源链 = A（已实施）；sys_sm = C（已实施）；registry = B 底座（代码在，`Dev_Start` 未启用）。
- **待实施**：registry 升级支持 C 模式（`SysModule_t` 加 `thread_entry/thread_stack` + `SYS_MODULE_REGISTER_THREAD`）；DI 采集（B）；通讯/轴仲裁（C）；霍尔测速（A）。
- **规则**：事件只发"跳变沿"；事件位≠状态≠数据（数据用队列/邮箱）；一个事件位单一消费者；跨任务共享变量 volatile/临界区。

## 11. 宏定义规范：统一放 .h ⚠️（2026-08-26）

- **Dev / Adp / Utils / Task 下所有 `#define` 一律放对应 .h**（配置、硬件定义、调试宏都在 .h），.c 只留函数实现与全局变量定义；
- 理由：配置集中可查、跨文件可复用、避免 .c 里散落魔法数字；
- **引脚/硬件绑定（端口/引脚/ADC 通道/EXTI 通道/复用功能码/IRQ）与其解释注释一律用宏放对应 .h，.c 只引用宏**——.c 里出现 `GPIO_PIN_09`、`ADC_CH4`、"PA4=电压" 这类字面量或引脚注释即为违规（2026-09-08：hc32_drv_adc.c 通道映射表 → hc32_drv_adc.h `ADC_DRV_VOLT_*`/`ADC_DRV_CUR_*`；hc32_drv_pwm.c TMR4 引脚复用 → hc32_drv_pwm.h `PWM_OUH~OVL_PORT/PIN`）；
- **同一绑定被多层引用时引用同一组宏，禁止双处字面量**（dev_adc.c 通道号 ↔ Adp 层映射：dev_adc.c include `Adp/hc32_drv_adc.h` 用 `ADC_DRV_VOLT_CH`/`ADC_DRV_CUR_CH`，保证换板只改 .h 一处；配置宏级 include 不影响 ops 运行时注入架构）；
- **初始化打印/运行日志不得硬编码引脚号**（如 "init U=PB9/PB8"）——换板后打印即过期误导，改为无引脚表述或引用宏；
- 特例：`SYS_SM_WAIT_EVENTS` 放 `dev_event_def.h`（事件掩码归事件定义）；`SYS_SM_THREAD_*` 放 `dev_model.h`；
- 注意：挪宏到 .h 时用删行脚本要逐行验证，别用跳过块逻辑（2026-08-26 曾因跳过块 bug 把 hc32_drv_adc.c 整个删空，链接报 undefined reference——见 §8）。

## 12. 外设寄存器写保护：先 LL_PERIPH_WE 解锁、写完 LL_PERIPH_WP 上锁 ⚠️（2026-08-30）

- **规则**：HC32F460 的 PWC FCG（外设时钟门控）、GPIO（引脚复用 FSEL / 引脚属性）、INTC（中断登录）、AOS 等寄存器处于**写保护域**——直接写会被**静默忽略**（不报错、不异常、寄存器保持原值）。写前必须 `LL_PERIPH_WE(域)` 解锁，写完 `LL_PERIPH_WP(域)` 上锁；
- 域宏在 `hc32_ll.h`：`LL_PERIPH_FCG`（时钟门控）、`LL_PERIPH_GPIO`（引脚复用/属性）、`LL_PERIPH_INTC`（中断登录）等；**新外设 bring-up 时第一件事：确认它的寄存器是否在写保护域、该用哪个域宏**（参照 hc_drv_timer / hc32_drv_adc 现成写法）；
- **正确模板**：

```c
/* 时钟门控（Adp\hc32_drv_pwm.c PwmHw_ChannelInit） */
LL_PERIPH_WE(LL_PERIPH_FCG);
FCG_Fcg2PeriphClockCmd(FCG2_PERIPH_TMRA_4, ENABLE);
LL_PERIPH_WP(LL_PERIPH_FCG);

/* 引脚复用（GPIO_SetFunc / GPIO_Init 同域） */
LL_PERIPH_WE(LL_PERIPH_GPIO);
GPIO_SetFunc(u8Port, u16Pin, PWM_GPIO_FUNC_TIMA);   /* PB7/PB9 → TMRA4，功能码 4 */
LL_PERIPH_WP(LL_PERIPH_GPIO);
```

- **反例（2026-08-30 PWM 移植，Adp\hc32_drv_pwm.c）**：TMRA4 时钟门控与 PB7/PB9 引脚复用两处都没解锁 → FCG 写入被忽略、引脚停留 GPIO 态 → **ops 被调用、日志全部正常、示波器上却无任何波形**。这类故障的迷惑性在于"软件链路看起来全对"，排查时要把"写保护域是否解锁"列为第一检查项；
- 注意：`FCG_Fcg2PeriphClockCmd` 等 DDL 函数内部**不做**解锁（只有 DDL_ASSERT 参数检查），不要以为调了官方 API 就等于写成功了。
