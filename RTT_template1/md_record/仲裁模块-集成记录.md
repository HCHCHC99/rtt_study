## 二、与既定方案的偏差（及理由）

1. **Axis_t 不嵌 `ArbData_t`，保留 dev_act 自持轴表**。原计划把仲裁数据嵌进 `Axis_t`，实施时放弃：仲裁互斥量生命周期收在 dev_act 内部，不受 IDLE 重初始化/任何对 `mySystem.axis` 的整块清零影响；且避免 `dev_model.h → dev_act.h` 的新增耦合。轴数一致性用运行期守卫兜底（Init 时比对 `ARB_MAX_AXIS_NUM != MAX_AXIS_NUM` 直接拒启）。外部访问统一走 `Arb_GetData/Arb_SetEnable`。
2. **`Arb_Module_Init` 返回值 rt_err_t → void**。`SysModule_t.init` 是 `void(*)(void)`，对齐工程现有模块签名（Polarity_Init 等均 void），失败路径已有 ARB_PRINT 报错。
3. **线程管理归 registry**。内核原自建线程，与 registry C 模式重复；改为只建 mq+互斥量，线程由注册块创建（优先级 15，勘查确认 8~18 区间空闲）。

## 三、运行时序（现状）

- main 早段 `Dev_RegisterAll`：注册 act → Init（建 mq + 双轴互斥量，enable=1）→ registry 建 "act" 线程（prio 15 / 栈 2048）；
- 每次 IDLE（上电/恢复）：`Dev_Registry_InitAll` → Init 幂等复位：四队列清空、状态归零、enable=1，mq/线程不动；
- 命令通道：输入源 `Arb_SendCommand`（ISR 安全）→ 仲裁线程 mutex 内改队列 + 决策 + 刷 Watch 调试变量。

## 五、遗留（第二波接线 agent 处理）

- 极性稳定跳变 → `Arb_SendCommand`（FWD/REV 允许、掉电/异常清允许）；
- 状态机 EMERGENCY 入口 → 双轴 `EMERGENCY_STOP`（urgent）；FAULT 入口 → 双轴 disable；
- FAULT→RUN 直接恢复路径（不经 IDLE，无 InitAll 复位）需显式 re-enable + 按极性当前态重发命令。

## 六、第二波接线（Avicenna）+ 主线程终审补丁

- dev_polarity：稳定跳变沿补发仲裁命令（FWD/REV → RUN_FWD/RUN_REV，掉电/异常 → 双 CLEAR_ALLOW），轴事件组保留不动；失败计数 + ARB_PRINT 告警；
- dev_state：EMERGENCY 双轴 urgent EMERGENCY_STOP；FAULT 双轴 disable；FAULT→RUN 恢复（enter_run 检测 prev==FAULT）显式 re-enable 并按 Polarity_GetState 重发；
- **终审补丁（主线程）**：跳转表存在 IDLE/RUN --EVT_SYS_FAULT--> FAULT 的直入路径（不经 EMERGENCY），原实现只 disable 不触发决策，残留 allow 会让硬件输出维持原状到下一条消息才停。enter_fault 现在补发 urgent EMERGENCY_STOP（对 EMERGENCY 路径幂等），保证任何 FAULT 入口硬件立即停。

## 七、链接期补漏（2026-08-28 15:17 构建报错）

- 现象：`rod_task.c:48` 链接报 `undefined reference to Arbitrator_GetDirection`。旧占位接口在内核替换后消失，但集成阶段只清了 main.c 的调用，漏查了 rod_task 这个调用方（教训：删符号前应全仓 rg 引用，不能只改注册点）。
- 修复：rod_task 改用 `Arb_GetData` 读取仲裁结果，枚举映射 `DIR_NONE/FWD/REV -> ROD_DIR_STOP/FWD/REV`；`enable==0` 或读取失败一律按 `ROD_DIR_STOP` 处理（disable 后无需等仲裁线程跑完决策，推杆状态机立即视为停止）。
- 验证：GCC 重编 rod_task.o 通过；nm 确认 rod_task.o 引用 `U Arb_GetData` 且 `Arbitrator_GetDirection` 引用清零，dev_act.o 导出 `T Arb_GetData/SendCommand/ThreadEntry`。CLI 全量链接时报的 `__locale_ctype_ptr` 为命令行 GCC 15.2.1 与 Studio 工具链 newlib 版本不匹配的噪音，与本次改动无关，Studio 内重新构建即可。

## 八、台架自测线程（无串口命令注入）

- 背景：无调试串口，msh 不可用；Debug makefile 是静态文件清单（新增 .c 不自动编入），故自测代码放 main.c 内，开关 `DEV_ENABLE_ARB_SELFTEST`（dev_config.h，量产置 0）。
- 形态：arbtst 线程（prio 24 / 栈 1024，入栈登记表），上电延时 3s 后按 3s 步进注入 8 步命令序列，覆盖：优先级压制（CAN>POWER）、阻塞/解除、同设备双向冲突、急停清队、恢复。每步决策由默认输出 ops 打一行 [ARB] 日志。
- 配套：`md_record\仲裁模块-测试指南.md`（预期日志与 Watch 检查表）。

## 九、INIT 卡死根因（2026-08-29 确认）：finsh 空转饿死低优先级线程

- 现象链：INIT 永不退出；`[SM_DIAG]` 显示 `cur=0 evt_flag=0x81 sys_sm=yes entered=0 recv=0`——sys_sm 线程创建成功但从未被调度。
- 根因：`RT_CONSOLE_DEVICE_NAME="uart4"`，但 `BSP_USING_UART4` 被注释（无串口硬件）→ uart4 设备不存在 → finsh 绑定 console 失败 → `finsh_getchar()` 立即返回 EOF → finsh 主循环 `if (ch<0) continue;` 成为 **prio 20 死循环** → 严格优先级抢占下 prio 22 的 sys_sm/di_task 永远饿死（di_task 饿死同时解释了极性测试无响应）。
- 修复：shell.c 的 EOF 分支加 `rt_thread_mdelay(10)` 让出 CPU（保留 finsh/msh，将来接串口仍可用；量产可再评估关 RT_USING_FINSH 省 RAM）。
- 教训：无输入源的 shell 组件在缺设备时会退化为忙等；引入任何 RT-Thread 组件前先确认其"资源缺失"路径是否让出 CPU。
