## 1. 背景与目标

把源工程 `app\power` 模块（母线电压 + 电流采样）移植到目标工程，采用
**表驱动 + 注册管理 + Adp/Dev/Utils 三层**的可移植架构。

本模块只作为**输入设备**：采样母线电压和电流，向上层提供数据；
**不依赖其他业务模块**（pwm / ctrl_current / pid / pos 等）。

## 4. 硬件资源与参数（已确认）

### 4.1 采样通道

| 项 | 母线电压 | 电流 |
|----|---------|------|
| 引脚 | **PA6** | PA5 |
| ADC1 通道 | **CH6**（`ADC1_PIN_PA6`） | CH5（`ADC1_PIN_PA5`） |
| 序列 | **SEQ_A（与电流同组）** | **SEQ_A（与电压同组）** |
| 功能使能 | `en_voltage = ENABLE` | `en_current = ENABLE` |
| 触发 | 软件触发（task 里启动）；预留硬件触发（TMR0_1 CH_B → AOS → EVT0） | 同左 |
| 中断 | EOCA（INT116，与电流同一次转换） | EOCA（INT116，与电压同一次转换） |
| verf / adc_res | 3.3V / 12bit | 3.3V / 12bit |

> **时间对齐**：电压（CH6）与电流（CH5）放在同一个 SEQ_A 单次转换，由同一次触发启动、同一次 EOCA 中断处理——两者采样时刻天然一致（采纳 HB 参考方案，优于原"电压 SEQ_A + 电流 SEQ_B"拆分）。

### 4.2 换算参数

**母线电压**（分压 100k 上 / 3.3k 下）：

```
Vadc = Vbus × 3.3k / (100k + 3.3k) = Vbus × 0.031946
vol_gain = (100k + 3.3k) / 3.3k = 31.303
vol_offset = 0.0
```

**电流**（传感器 `VOUT = VREF + IP(A) × 264 mV/A`，VREF = 1.65V）：

```
IP(mA) = (Vadc - 1.65) × 1000 / 0.264 = (Vadc - 1.65) × 3787.88
cur_gain   = 1000 / 0.264 ≈ 3787.88
cur_offset = -1.65 × 3787.88 ≈ -6250.0
```

⚠️ 取绝对值：`current = fabsf((adc × verf / (1<<res)) × cur_gain + cur_offset)`
（`power_upd.current` 从 `uint16_t` 改为 **float**，消除无符号截断隐患）

### 4.3 量程与精度

| 项目 | 数值 |
|------|------|
| 母线电压满量程 | 3.3V × 31.303 ≈ 103.3V |
| 电压分辨率 | ≈ 25.2 mV/LSB |
| 电流满量程 | (3.3-1.65)/0.264 = 6.25A |
| 电流分辨率 | ≈ 3.05 mA/LSB |
| 环形缓冲 | 每设备 256 × float（可配 `POWER_DATA_BUFFER_SIZE`） |

## 6. 参考实现（HB_chuchai v6.0.3 的 Adc.c/h）

> 来源：`D:\HB_chuchai_v.6.0.3\HC32F460_DDL_Rev3.3.0\projects\ev_hc32f460_lqfp100_v2\Adp\Adc.c/.h`
> 该工程（电机霍尔方案，HC32F460）的 Adp/Dev 分层与本设计高度一致，作为参考实现。

### 6.1 参考实现结构（Adc.c/h）

| 能力 | 实现 |
|------|------|
| 多实例 | `s_astcAdcInstances[8]` + `Adc_Create(config)`（查重、分配 ID）+ `Adc_Init()` 一次性初始化 |
| 每通道模式 | 中断 / DMA 可选（`en_adc_mode_t`） |
| 硬件触发链 | TMR0_1 CH_B（`ADC_SAMPLE_INTERVAL_US=50`，20kHz）→ AOS 路由（`AOS_ADC1_0 ← EVT_SRC_TMR0_1_CMP_B`）→ ADC1 SEQ_A → EOCA → INT116 → `ADC1_SeqA_IrqCallback` |
| 中断处理 | `Adc_ProcessInterruptChannels()`：只读原始值 + 存 `u16LatestValue` + 调 `pfnCallback(值, 通道)`（换算不放中断） |
| 换算 | `Adc_CalcVoltage = adc × 3.3 / 4096 × 1000 (mV)` |

### 6.2 Adp\hc32_drv_adc 以 Adc.c/h 为基座（决策 #11）

**直接搬**（纯 DDL，无 RTOS 依赖）：
实例表、`Adc_Create/Init/Start/Stop`、`Adc_InitConfig/SetPinAnalogMode/ChCmd`、`Adc_HardTriggerConfig`、`Timer0_Config`、`Adc_IrqConfig/EnableInterrupt`、`ADC1_SeqA_IrqCallback`、`Adc_ProcessInterruptChannels`、`Adc_CalcVoltage`。

**要裁剪**：
- DMA 模式（依赖 `Dma.h`）：暂不用，裁掉 `s_bHasDmaInstance / s_a8AdcIdToDmaId / Dma_*` 相关（保留为后续扩展点）
- PA7 调试翻转（`ADC_DEBUG_TOGGLE_ENABLE`）：建议保留，便于示波器验证采样间隔

**要换依赖**：

| 源工程 | 目标工程 |
|--------|----------|
| `main.h` / `Hardware.h` | 去掉；时钟频率宏用目标工程实际 PCLK1 |
| `TickTimer.h`（`tickTimer_GetCount`） | `rt_tick_get()` |
| `Gpio_io.h`（`Output_GPIO_Init/GPIO_TOGGLE`） | board/drv_gpio 或 DDL 直接写 |
| `rtt_log.h`（`MAIN_D`） | 目标工程 RTT 目录已有，保留 |
| `Aos.c` 的 `AOS_Connect(...)` | 并入 `adc_drv` 的 init（源工程在 `Hardware_Init` 里调，别漏） |

**RT-Thread 适配**：
- 中断：`INTC_IrqSignIn + NVIC` 直接配置可行，抢占优先级分组按 RT-Thread 要求（通常 4 位抢占优先级），与 RT-Thread 临界区协调
- 时间基准：`rt_tick_get()`

### 6.3 50µs（20kHz）采样的注意点

- `Timer0_Config` 在 DIV256 下：比较值 = PCLK1/256/20000 - 1；PCLK1=100MHz → 比较值≈18，量化误差约 ±5%（采样用无妨，需实测确认）
- **20kHz 超出 HB 文档验证范围**：其采样间隔表里 100µs(10kHz) 已标注"极限，需验证"，50µs(20kHz) 更高一档，**必须实测比较值精度/抖动/EOCA 触发稳定性**
- **20kHz 中断里禁止浮点换算/滤波**：中断只存原始值，换算放传感器任务（参考实现与本设计一致）
- 中断频率 × 2 通道，注意 CPU 负载预算

### 6.4 资源冲突检查（移植前）

- TMR0_1 CH_B：参考工程历史上有过冲突（原 Timer0_Unit1 管 CH_B 被 Adc.c 覆盖）；目标工程需确认 TMR0_1 是否被 RT-Thread tick 或其他模块占用
- AOS_ADC1_0 路由是否被其他外设占用

## 7. 注册条目（初始 3 个）

```c
void Dev_RegisterAll(void)
```

- `cur`：周期 5ms 读缓冲/滤波/状态

注册表职责：**设备清单 + 初始化顺序 + 周期字段**；task 执行交给 RT-Thread。

## 8. 与 RT-Thread 的衔接（替代关系）

| 源工程组件 | 新工程方案 |
|-----------|-----------|
| `event_group.c/h` | RT-Thread `rt_event`（`rt_event_create/send/recv`，支持阻塞等待 + 超时，中断可发送） |
| `sys_sched.c/h` 裸机调度 | RT-Thread 线程承载：一个"设备管理线程"按注册表周期遍历执行各 task |
| `sys_init.c` 注册机制 | `Dev_RegisterAll()` 集中注册（保留注册表管理感）；或后续换 `INIT_APP_EXPORT` |
| `sys_tick`（`SysTick_GetTick`） | `rt_tick_get()` |
| `msg_pubsub`（`Msg_Publish`） | 暂不移植，对外用 `GetInfo` 轮询；后续可接 `rt_mq` 消息队列 |

### 8.1 设备管理线程（推荐）

```
rt_thread_create("dev", Dev_Thread_Entry, ...)
Dev_Thread_Entry: 循环 { 遍历注册表, 按 period 调用 task, rt_thread_mdelay(1) }
```

- 优先级映射：源 prio 小→高；映射到 RT-Thread 线程优先级（数字大→低，方向相反，需换算）
- 若以后有实时性要求（如电流环 20kHz），把对应 task 移到独立高优先级线程

## 9. 数据流

```
[ADC1 中断]（SEQ_A 一次转换同时采 CH6 电压 + CH5 电流）
   EOCA → Adp_Adc_Irq → 换算电压 → 电压环形缓冲
                        换算电流(绝对值) → 电流环形缓冲
        ↑
[dev_adc task] 周期触发（软件触发 ADC_Start；硬件触发 TMR0_1 → AOS → EVT0）

[设备管理线程]
   bus_voltage task  → 读电压缓冲 → 均值 → 过压/欠压判定 → BusVoltage_GetInfo
   current_sensor task → 读电流缓冲 → 滤波 → 过流判定 → CurrentSensor_GetInfo

[上层] 轮询 GetInfo 获取电压/电流/状态
```

### 8. ADC 500us 硬件触发 + 1ms ISR 检测（2026-08-25）

- 需求：ADC 采样间隔 **500us（中断触发，2kHz）**；电流/电压检测间隔 **1ms（中断触发）**。
- 参考：`HB_chuchai_v.6.0.4\新过流方案.md` + `Adp\Adc.c(.h)`、`Adp\Aos.c(.h)`、`Adp\Timer0_Unit2.c(.h)`、`Dev\dev_adc(.h/.c)`、`Dev\dev_sensor(.h/.c)`、`Dev\dev_voltage(.h/.c)`。

**数据流：**
```
TMR0_1 CH_B (500us) --AOS 事件路由--> ADC1 SEQ_A 硬件触发 --> EOCA 中断
      EOCA ISR：读 CH6/CH5 原始值 -> 换算写环形缓冲 + 维护 20 点(10ms)滑动窗口和
TMR0_2 CH_A (1ms) 中断 --> Dev_Power_Isr1ms()
      --> BusVoltage_Isr1ms / CurrentSensor_Isr1ms
      （读 Dev_Adc_GetMean 10ms 滑动均值 -> 阈值判定 -> Sys_Event_Send，rt_event ISR 安全）
sys_sm 线程：rt_event_recv -> Sys_State_Dispatch
      （打印 over volt/under volt/over curr + 记故障码）-> 表驱动 -> EMERGENCY -> FAULT
```

**改动文件：**
- `Adp/hc32_drv_adc.h/.c`：`ADC_SAMPLE_INTERVAL_US=500U`；TMR0_1 CH_B + `AOS_SetTriggerEventSrc(AOS_ADC1_0, EVT_SRC_TMR0_1_CMP_B)` + `ADC_TriggerConfig(SEQ_A, ADC_HARDTRIG_EVT0)`/`Cmd(ENABLE)`；`AdcDrv_Start`=启动 TMR0_1；EOCA ISR 维护 20 点滑动窗口；新增 `AdcDrv_GetMean`（滑动均值，已换算工程值）。
- `Adp/hc_drv_timer.h/.c`：新增 `HcDrv_Timer_Start1ms(cb)`：TMR0_2 CH_A 1ms CMP 中断（PCLK1/64，INT007，INTC_IrqSignIn 回调，优先级 DDL_IRQ_PRIO_03），ISR 用 rt_interrupt_enter/leave 包裹后调回调。
- `Dev/dev_adc/dev_adc_ops.h`：新增 `ADC_MEAN_WINDOW_SAMPLES(20U)`（=10ms@2kHz，接口层宏）；ops 新增 `get_mean`。
- `Dev/dev_adc/dev_adc.c/.h`：删 `Dev_Adc_Task`（软件触发），新增 `Dev_Adc_Start/Stop` + `Dev_Adc_GetMean`。
- `Dev/dev_power/dev_cur_sensor.c/.h`：`Task` → `CurrentSensor_Isr1ms`（1ms ISR：读均值 + 50ms 窗口过流；打印挪到线程）。
- `Dev/dev_power/dev_bus_voltage.c/.h`：`Task` → `BusVoltage_Isr1ms`（1ms ISR：读均值 + 23V/0V 迟滞 + 3000ms 恢复延时计数）。
- `Dev/dev_power/dev_power_isr.c/.h`（新）：`Dev_Power_Isr1ms()` 分发电压/电流。
- `Dev/dev_registry.c`：adc/cur/vm 注册 task=RT_NULL，仅保留 init + register 打印（ISR 驱动）；`Dev_Start` 不再调用（线程留给未来线程型设备）。
- `Dev/dev_mgr/dev_state.c`：`Sys_State_Dispatch` 增加 `POWER_PRINT`（over volt/under volt/over curr）——故障打印从 ISR 挪到线程上下文。
- `applications/main.c`：初始化顺序 = UsTimer → Dev_Adc_Bind + Dev_RegisterAll → RttManager_DumpSwitches → App_Model_Init（先建 sys_evt）→ HcDrv_Timer_Start1ms(Dev_Power_Isr1ms) → Dev_Adc_Start() → Sys_Sm_Thread_Start。

**参数换算（PCLK1=100MHz）：**
- ADC 触发 TMR0_1：div256 → 390625Hz；500us → compare=(390625/2000)-1=194（实际 499.2us，误差 0.16%）
- 1ms 心跳 TMR0_2：div64 → 1.5625MHz；1ms → compare=(1562500/1000)-1=1561
- 滑动窗口 20 点 = 10ms @ 2kHz；过流窗口 50ms = 50 次 1ms 计数；电压恢复延时 3000ms = 3000 次计数

**构建前提（已确认无需改 DDL）：**
- `hc32f460_ddl/SConscript` 已编译 `hc32_ll_aos.c`（无条件）+ `hc32_ll_tmr0.c`（随 RT_USING_SERIAL）；`.cproject` 排除列表无 aos/tmr0/tmr6。
- 中断机制：`IRQ007_Handler` 由 `hc32_ll_interrupts.c` 分发到 `INTC_IrqSignIn` 注册的回调（与 ADC EOCA 同机制）。
- 编译验证：armcc（--cpu Cortex-M4 --apcs=interwork --c99 + 完整 include/宏）逐文件 9 个改动文件 0 error。

**注意事项：**
- 1ms ISR 内不打印（打印在 sys_sm 线程）；ISR 只做均值读取、阈值判定、rt_event_send。
- EOCA 优先级 06、TMR0_2 优先级 03；滑动和/环形缓冲为单次 32/16 位写，原子。
- Keil 工程未含 tmr0/aos 源文件，用 Keil 需手动加（本次以 Studio 为主）。
- ⚠️ 安全：1ms 检测适合故障管理/状态机；真正硬件级过流保护（<1ms）建议比较器或 EOCA 逐样本比对。
