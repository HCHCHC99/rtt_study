# 堆栈管理（线程栈统一 + 内存观测）

> 记录日期：2026-08-27
> 状态：**已实施**（task_stack.h 统一管理；2026-08-27 新增任务级哨兵水位跟踪）

---

## 一、为什么需要统一管理

- 早期各线程栈大小散落在各 task 头文件 / rtconfig.h 里，改一处容易漏；
- rod 线程 1024B 栈溢出导致 HardFault（详见 `stack溢出修复.md`）；
- 需要一眼看清"每个线程配了多少栈、总共多少、还剩多少堆"。

**结论：`Task/task_stack.h` 成为所有线程栈大小的唯一权威来源（Single Source of Truth）。**

---

## 二、task_stack.h 统一宏（唯一数值来源）

```c
#define TASK_STACK_MAIN     (4096U)   /* main 主线程：初始化 + 1s 采样打印 + MSH */
#define TASK_STACK_SYS_SM   (2048U)   /* sys_sm 系统状态机事件线程 */
#define TASK_STACK_DEV      (2048U)   /* dev 设备管理线程 */
#define TASK_STACK_ROD      (2048U)   /* rod 推杆位置/状态（含 float+RTT 打印+中断嵌套；1024 曾溢出） */
#define TASK_STACK_DI       (1024U)   /* di DI 采集（2ms 极性扫描） */
#define TASK_STACK_LED      (1024U)   /* led LED 1s 翻转 */
#define TASK_STACK_FINSH    (4096U)   /* finsh MSH shell */
#define TASK_STACK_IDLE     (256U)    /* idle 空闲线程 */
#define TASK_STACK_WORKQ    (2048U)   /* workq 系统工作队列 */
#define TASK_STACK_TIMER    (512U)    /* timer 软定时器线程 */
```

各引用处（宏引用宏，改一处全同步）：

| 文件 | 宏 |
|---|---|
| `Task/rod_task.h` | `ROD_THREAD_STACK = TASK_STACK_ROD` |
| `Task/di_task.h` | `DI_THREAD_STACK = TASK_STACK_DI` |
| `Task/led_task.h` | `LED_THREAD_STACK = TASK_STACK_LED` |
| `Dev/dev_mgr/dev_model.h` | `SYS_SM_THREAD_STACK = TASK_STACK_SYS_SM` |
| `Dev/dev_registry.h` | `DEV_THREAD_STACK_SIZE = TASK_STACK_DEV` |
| `rtconfig.h` | `RT_MAIN/FINSH/IDLE/WORKQUEUE/TIMER_THREAD_STACKSIZE = TASK_STACK_*` |

打印函数：`Task_Stack_Dump()`（main.c 调用，开关 `TASK_STACK_PRINT_EN` 在 rtt_manager.h）。

## 三、内存布局（HC32F460，188KB SRAM）

```
0x1FFF8000 ┌────────────────────────────┐
           │ .data + .bss（静态区）      │  ← HEAP_BEGIN = &__bss_end
           ├────────────────────────────┤
           │ RT-Thread 系统堆（HEAP）     │  ← 所有 rt_malloc 从这里切
           │  · 线程栈（动态分配）        │     · 内核对象（事件/信号量/队列）
           │  · RTT 缓冲区 / finsh 等    │
           └────────────────────────────┘
0x1FFF8000 + 188KB = HEAP_END
```

- 芯片：HC32F460xE（512K Flash / 188K SRAM）；
- `board/board.h`：`HC32_SRAM_SIZE=188`，`HEAP_END = 0x1FFF8000 + 188KB`；
- `link.ld`：`RAM: ORIGIN=0x1FFF8000, LENGTH=188K`；
- 启动文件 `.s` 的 `Stack_Size=0x2000(8KB)` 是**启动主栈 MSP**，不是线程栈；线程栈运行时从堆分配。

## 四、观测方法（能看什么）

| 手段 | 看什么 | 命令/API |
|---|---|---|
| `Task_Stack_Dump()` | 每个线程配置的栈大小 + 总栈 + 堆 total/used/max/free | 自定义（MAIN_D） |
| 周期告警 | 登记线程超阈值时打印当前剩余量；`min_free` 字段可通过调试器 Watch 观察 | 自定义（MAIN_D） |
| `rt_memory_info()` | 堆：总量 / 已用 / 峰值已用 | `rtthread.h` |
| `list_thread`（MSH） | 每个线程：栈 size / **max used** / 剩余 | finsh 内置 |
| `list_memheap` / `memtrace`（MSH） | 堆内所有分配块（地址/大小） | small_mem 内置 |
| `.map` 文件 | 静态 .data/.bss 精确占用 | 链接产物 |
| `RT_USING_STACK_CHECK` | 栈溢出时打印 `thread:xxx stack overflow` | rtconfig.h 已开 |

## 五、局限性与结论（关键认知）

- **任务哨兵水位规则**：RT-Thread 初始化线程时把整栈填成 `'#'(0x23)`；Cortex-M 栈向低地址增长，从 `stack_addr` 开始连续 `#` 的字节数就是当前剩余量。周期监控会按线程名匹配登记表，保存运行以来的最低值 `min_free`。注意内核实际名称是 `tshell / tidle0 / sys workq / timer`，不能用 `finsh / idle / workq` 匹配。
- 未在 `s_task_stack[]` 登记的系统线程仍会被 `Task_Stack_Monitor()` 遍历并做超阈值告警，但没有跨周期的 `min_free` 记录。

- **"剩余堆"可以精确打印**：`heap free = total - used`（rt_memory_info 已提供）；
- **"每个别的东西花了多少堆"无法自动精确拆分**：
  - RT-Thread 的 `rt_malloc` 只记大小、不记"申请者身份"，堆块没有名字；
  - 线程栈、事件、信号量、队列、RTT 缓冲等都混在同一堆里；
  - 只能**近似拆分**：`list_thread` 看线程栈 max used，`memtrace` 看各块大小，`list_memheap` 看总量，再人工归因。
- 所以：**打印"剩余/可用"是准的；打印"哪一项具体吃了几字节"需要人工用 MSH 命令 + map 文件拼出来，没有现成的一行 API。**
