# 仲裁内核移植实施记录

日期：2026-08-28

## 移植范围

本次只改写 `Dev/dev_act/dev_act.h` 和 `Dev/dev_act/dev_act.c`，并新增本记录；未修改 `dev_model.h`、`dev_registry`、`rtt_manager.h`、`dev_config.h` 或 `Dev/dev_act/SConscript`。原占位版 `dev_act` 实现被替换为消息队列 + 互斥量 + 仲裁线程方案。

已移植的核心部分：

- GPT 第三节的类型定义：`ArbCmdType_t`、`ArbDeviceId_t`、`ArbPriority_t`、`ArbCommandMsg_t`、`ArbCommandRecord_t`、`ArbCommandQueue_t`、`ArbData_t`。
- 优先级表保留 GPT 版：`PRIO_EMERGENCY=0`、`PRIO_LIMIT=1`、`PRIO_FAULT=2`、`PRIO_MANUAL=3`、`PRIO_CAN=4`、`PRIO_POWER=5`、`PRIO_NONE=255`。
- GPT 4.3 的 `Arb_ProcessMessage`。
- GPT 4.4 的 `Arb_CmdListRemove`、`Arb_CmdListSetAllow`、`Arb_CmdListSetBlock`、`Arb_CmdListClearAll`。
- GPT 4.5 的 `Arb_Decision` 和 `Arb_ApplyStop`。
- 模块初始化：`rt_mq_create("arb_mq", 16, sizeof(ArbCommandMsg_t), RT_IPC_FLAG_FIFO)`、每轴 `rt_mutex_init(..., RT_IPC_FLAG_PRIO)`、创建并启动 2048 栈/优先级 15/时间片 10 的仲裁线程。
- ISR 侧发送：`Arb_SendCommand` 使用 `rt_mq_send`；`urgent` 非零时使用 `rt_mq_urgent`。函数内部只做校验和入队，不等待、不打印。
- 对外接口：`Arb_Module_Init`、`Arb_SendCommand`、`Arb_SetEnable`、`Arb_GetData`、`Arb_BindOutputOps`。
- 输出抽象：`ArbOutputOps_t` 的 `fwd/rev/stop`，默认实现只打印轴号和整型 `duty`，不打印浮点。
- 调试观测：四队列 count、`active_device_id`、`active_dir`、`state`、`conflict_fault`、仲裁计数和 `ArbData_t * volatile g_arb_dbg_watch`；仲裁线程每次决策后刷新。未添加 MSH 命令。

## 与 GPT 文档的差异

1. **`float param` 改为 `uint8_t duty_pct`**  
   `ArbCommandMsg_t.param`、`ArbCommandRecord_t.param` 和原 `current_duty` 都改为 0~100 整型。`ArbData_t` 使用 `duty_pct` 字段。原因是开发规范禁止打印浮点，且占空比百分比用整型已满足当前需求，同时减小消息体。

2. **方向/状态类型做了模块化命名**  
   GPT 使用 `MotorDir_t`、`MotorState_t` 和 `DIR_*`、`MS_*`。本工程没有这两个电机类型定义，因此新增 `ArbDir_t`、`ArbState_t`，但保留 `DIR_NONE/FWD/REV`、`MS_IDLE/RUNNING` 的枚举值语义。

3. **没有把字段挂进现有 `Axis_t`**  
   GPT 的 `Axis_t` 会追加 `ArbData_t arb` 和 `rt_mutex_t arb_mutex`，并访问 `mySystem.axis[]`。因为本次禁止修改 `dev_model.h`，模块内部定义了 `ArbAxis_t`，自持 `ArbData_t` 和静态互斥对象。后续集成阶段再完成 `Axis_t` 挂接。

4. **互斥对象按本工程 RT-Thread 头文件适配**  
   当前 RT-Thread 将 `rt_mutex_t` 定义为 `struct rt_mutex *`。为保留静态初始化 API，内部字段使用 `struct rt_mutex arb_mutex`，调用 `rt_mutex_init/take/release` 时传一级指针。这里不能照抄 GPT 中 `rt_mutex_t arb_mutex` 后再取地址的写法。

5. **增加输出 ops 抽象**  
   GPT 直接调用 `Motor_OnArbitrationFwd/Rev/Stop`。本工程改为 `ArbOutputOps_t` 函数指针表和默认空输出实现，避免本模块依赖尚未集成的 PWM/GPIO。

6. **发送侧参数校验更严格**  
   GPT 只示例检查 `axis_id`。现在未初始化、轴号、来源设备号、优先级、命令类型、占空比非法时静默返回错误码；不打印，不修改状态。这样 ISR 调用更安全。

7. **失败路径增加资源回收**  
   GPT 初始化失败后直接返回。现在线程创建或启动失败时会删除已创建的 mq/thread 并清空句柄，避免重复初始化时留下悬挂资源。

8. **调试变量刷新时机改为决策后统一刷新**  
   裸机版本在队列操作过程中即时更新部分 Keil Watch 变量。本工程按当前事件设计要求，由仲裁线程在 `Arb_Decision` 后统一刷新，队列操作函数自身不访问全局调试变量。

9. **打印入口等待集成宏**  
   `dev_act.c` 已包含 `applications/rtt_manager.h` 并直接使用 `ARB_PRINT`。当前 `rtt_manager.h` 还没有 `ARB_PRINT_EN/ARB_PRINT`，集成阶段统一补齐；本次没有为编译通过而修改该文件。

## 保留的裸机语义

- `allow` 插入前检查对应 `block` 队列：`block` 非空时拒绝写入。
- `allow` 按优先级数值从小到大排序；同优先级命令保持先到者在前的稳定顺序。
- `block` 按 FIFO 追加，且同一 `device_id` 不重复添加。
- `RUN_FWD/RUN_REV` 先移除自己的对应 `block`，再写入自己的 `allow`。
- `STOP` 只移除自己的双向 `allow`，不添加 `block`。
- `CLEAR_ALLOW_*` 和紧急停止只清 `allow`，保留 `block`。
- 决策时对应 `block` 非空则该方向没有候选命令。
- 双向最高优先级命令来源相同，或双向最高优先级数值相同，置 `conflict_fault=1` 并停机。
- 双向最高优先级不同时，数值小者胜出。
- 有有效命令时更新 `active_device_id`、`active_dir`、`duty_pct`、`state` 并调用输出接口；无有效命令或未使能时走停机。
- 未使能时按 GPT 逻辑提前停机，不推进 `last_arbitration_time` 和 `arbitration_count`。
