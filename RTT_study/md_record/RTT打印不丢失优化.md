# RTT 打印不丢失优化

> 记录日期：2026-08-30
> 适用：HC32F460 + SEGGER RTT（J-Link SWD）

---

## 一、丢打印机理

RTT 上行是环形缓冲，本工程原配 **1KB**（`SEGGER_RTT.c: BUFFER_SIZE_UP`），模式 **`NO_BLOCK_SKIP`**：缓冲剩余空间放不下**整条**消息时，**整条静默丢弃**。

J-Link 经 SWD 异步排空缓冲（速度受 RTT Viewer 轮询间隔限制），200MHz CPU 的打印突发轻松跑赢它 → 缓冲瞬时打满 → 丢行。两个经验现象均由此解释：

1. **断点单步时打印"出现"**：CPU 停止写入，J-Link 继续排空，断点处的行被完整搬走；
2. **打印后加 1us 延时就"成功"**：给了排空让时间（严格说 1us 往往不够，起作用的是"延时恰好跨过一次 Viewer 轮询"）。

## 二、本工程修复

1. `SEGGER_RTT.c`：`BUFFER_SIZE_UP` 1024 → **4096**（3KB RAM 换启动期突发不溢出，性价比最高）。
2. `rtt_log.h` 新增 **`MAIN_D_SYNC`**：打印后 `rt_hw_us_delay(200)` 忙等，给排空让时间。用于**启动段/关键转移/低频诊断**（状态机 enter、INIT 链路诊断、task 入口标记）。
3. 高频路径（1ms/周期循环内）仍用普通 `XXX_PRINT`，不得用 SYNC 拖慢实时性。

## 三、使用准则

| 场景 | 用法 |
|---|---|
| 启动序列、状态跳转、一次性诊断 | `MAIN_D_SYNC`（或打印后手动 `rt_hw_us_delay(200)`） |
| 周期性运行打印 | 普通 `XXX_PRINT`，接受偶发丢失 |
| 绝对不能丢的连续观测 | 改用 Watch 变量/计数器（打印本质上不可靠），或调试器暂停读内存 |
| 量产 | 关打印开关 + 可将 RTT 缓冲改回 1KB 省内存 |

## 四、附加要点

1. **判状态用变量，不用打印**：`[SYS_MON]/[SM_DIAG]` 读的是 `sys_sm.cur_state` 等变量，丢打印不影响判断。INIT 卡死排查中"看起来 INIT 没动"与"打印丢了"曾被混在一起，靠变量判据才分干净。
2. RTT Viewer 的读取间隔设置直接影响排空速度；连接时机晚于启动会丢失缓冲已滚动覆盖的早期行（本工程启动段约 1.7KB，4KB 缓冲下不再滚动）。
3. `SEGGER_RTT_MODE_BLOCK_IF_FIFO_FULL` 可零丢失，但无调试器 attached 时 CPU 会卡死在打印上——只允许台架临时使用，严禁量产。
