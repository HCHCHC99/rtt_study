# 电机仲裁模块测试指南

> 记录日期：2026-08-28
> 前提：无调试串口（仅 SWD）；日志走 RTT；命令注入用 main.c 内置自测线程（`DEV_ENABLE_ARB_SELFTEST=1`）

---

## 一、准备

1. Studio 重新 Build + 烧录（本次改了 main.c/task_stack/dev_config，会全量重编这几个文件）。
2. 打开 J-Link RTT Viewer：选 J-Link → SWD → 目标器件 HC32F460 → 附加到运行目标，即可看 `[ARB]` 日志（`ARB_PRINT_EN=1` 已开）。
3. 调试器附加（不复位），Watch 添加：`g_arb_dbg_watch`、`g_arb_dbg_allow_fwd_count`、`g_arb_dbg_allow_rev_count`、`g_arb_dbg_block_fwd_count`、`g_arb_dbg_active_dir`、`g_arb_dbg_active_device_id`、`g_arb_dbg_state`、`g_arb_dbg_conflict_fault`、`g_arb_dbg_arbitration_count`。

## 二、上电冒烟（只看日志）

预期顺序：

```
[DEV_REG] register act
[ARB] init axis=2 mq=16 prio=15      <- Dev_RegisterAll 阶段
[SYS_STATE] enter IDLE
[ARB] reset axis=2                    <- IDLE 入口 InitAll 幂等复位
Task_Stack 打印含 act=2048 / arbtst=1024
[ARB] selftest start                  <- 上电约 3s 后
```

通过标准：无 Oops/assert、`act` 线程不出现在栈水位 WARN 里、`g_arb_dbg_watch` 非空。

## 三、仲裁自测序列（核心用例）

每步间隔 3s，每步恰好一行 `[ARB]` 决策日志 + 一行 st 注释日志：

| 步骤 | 注入 | 预期 [ARB] 决策 | Watch 检查点 |
|---|---|---|---|
| st1 | POWER_POS RUN_FWD 85 | `fwd duty=85` | dir=1 dev=1 state=1 allow_fwd=1 |
| st2 | CAN RUN_REV 70（优先级 4 压过 5） | `rev duty=70` | dir=2 dev=5 allow_rev=1 |
| st3 | LIMIT_FWD BLOCK_FWD（urgent） | `rev duty=70`（不变） | block_fwd=1 |
| st4 | LIMIT_FWD UNBLOCK_FWD | `rev duty=70`（不变） | block_fwd=0 |
| st5 | CAN RUN_FWD（同设备已持 REV） | `stop duty=0` | conflict=1 state=0 dir=0 |
| st6 | EMERGENCY 急停 | `stop duty=0` | allow_fwd=0 allow_rev=0 |
| st7 | POWER_POS RUN_FWD 85 | `fwd duty=85` | state=1（conflict 已被新决策清 0） |
| st8 | EMERGENCY 急停 | `stop duty=0` | 全零，`[ARB] selftest done` |

同时观察 `[ROD]`（ROD_PRINT_EN=1）：rod_task 消费 `Arb_GetData`，st1/st2/st5/st7/st8 时推杆状态机应跟随方向变化。

## 四、故障联动（真实链路，不改代码）

1. 运行中（st7 之后）调试器把 `g_volt_cfg.over_th` 改到当前母线电压以下（如 10000mV 以下按实际电压定）；
2. 预期：1ms ISR 跳变 → `[POWER]` 过压 → `[SYS_STATE]` EMERGENCY→FAULT，EMERGENCY 时双轴 urgent 急停 → `[ARB] axis0 stop`，FAULT 时 `Arb_SetEnable(0)`；
3. 把 `over_th` 改回 23000 → 约 500ms 后电压自动恢复 → 状态机回 RUN（prev_state）→ 日志 `act resync from fault` → 按 Polarity_GetState 重发命令。
4. 过流走手动恢复：同法改 `g_cur_cfg.over_th_ma` 触发，FAULT 后确认仲裁 enable=0（电机不再响应任何 allow）。

## 五、真实极性（如已接执行器电源）

- 切换外部电源正/反向 → `[POLARITY]` 跳变打印 + 10ms 内 `[ARB] fwd/rev` 决策；
- 断电（P=N=0）→ 双 CLEAR_ALLOW → `[ARB] stop`；
- 注意：极性脚悬空时双窗口大概率判 UNKNOWN（不发事件），若实测稳定 0 电平会周期性清 allow——悬空台架出现 `[ARB] stop` 先查 `[POLARITY]` 日志。

## 六、当前边界（避免误判）

1. 输出 ops 是默认空实现（只打日志）——`fwd/rev/stop` 只代表仲裁结果，电机不真转；接 PWM 时 `Arb_BindOutputOps` 换绑。
2. 上下限位开关尚未接入仲裁 BLOCK（rod_task 只读电平进状态模块），st3 的限位阻塞是自测模拟，真实限位保护待接线。
3. 过流手动恢复路径自测没覆盖（无 console 无法调 `Sys_State_Recover`），需要时可在调试器里临时置事件位或后续加 debug 钩子。

## 七、RTT 丢打印问题（2026-08-29 确认并修复）

- 现象：全速运行时偶发丢行，断点单步或打印后加 1us 延时就能看到。
- 原因：RTT 上行缓冲仅 1KB（BUFFER_SIZE_UP），模式 `NO_BLOCK_SKIP`——缓冲放不下整条消息时**整条丢弃**；J-Link 经 SWD 异步排空缓冲，速度跟不上 200MHz CPU 的打印突发。断点停机后 CPU 停写、J-Link 继续排空 → 单步全可见；加延时给排空留时间 → 打印出现。
- 修复：`SEGGER_RTT.c` 的 `BUFFER_SIZE_UP` 1KB→4KB；`rtt_log.h` 新增 `MAIN_D_SYNC`（写后忙等 200us），状态机转移/INIT 链路诊断打印已切换；其余高频路径仍用普通打印。
- 注意：丢打印只影响观测，不影响逻辑——`[SYS_MON] sm: sys=INIT` 读的是状态变量，不是打印；判状态以变量为准。
